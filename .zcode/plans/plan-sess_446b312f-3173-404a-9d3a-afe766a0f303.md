## Plan: Step-count accuracy fix + Barcode scanner (with AI photo fallback)

### Part 1 — Step counter fix (balanced, per your choice)

**Root cause:** the accelerometer detector (identical in native `WalkTrackerService.kt` `detectAccelStep` and JS fallback `src/utils/stepDetector.js`) counts a step when the magnitude swings > 0.9 m/s² from a slow baseline, then falls below 0.4. There is no dwell requirement, the threshold is low enough that a quick wrist/phone move trips it, the baseline chases slow orientation changes, and 280 ms re-arm lets two fidgets count twice.

**Changes (mirrored in both files):**
- Peak (arm) threshold 0.9 → **1.3 m/s²**; disarm 0.4 → **0.55**
- Minimum re-arm interval 280 ms → **320 ms**
- New: **dwell time** — the deviation must stay above the peak for ≥ **100 ms** before the step can complete (rejects single-sample blips, typing jitter)
- New: **tilt cut-off** — if the detector stays "armed" for > **800 ms** without completing (sustained tilt, phone laid down), it resets without counting and re-anchors the baseline (kills orientation-change false positives)
- Baseline no longer updates while armed (a step's own signal can't drag the baseline toward it)

No changes to stride, distance, GPS, or route logic — steps remain `max(hardware counter, accel)`.

**Validation:** node test with synthetic signals (walking sinusoid → counts ~1/cycle; ±0.5 jitter → 0; quick tilt impulse → 0); then `npm run build`, `cap sync android`, `gradlew :app:assembleDebug`. Final on-phone walk test (your device — no emulator can simulate real motion).

### Part 2 — Barcode scanner, with AI photo fallback (per your choice)

**New dependency:** `@capacitor/mlkit-barcode-scanning` (official Capacitor 8 plugin; on-device ML Kit, offline, no API key; ~2 MB model). Install, `npx cap sync android`, add `CAMERA` permission + `<uses-feature android.hardware.camera required=false>` to `AndroidManifest.xml` (same pattern as the location permissions). Confirm the exact JS API from its README at install time (expected: `scan()` → `{ code, canceled, allowed }`, `stopScan()`, `isSupported()`, Barcode `rawValue`/`format`).

**New module `src/utils/barcode.js`:** EAN/UPC normalization (leading-zero cleanup + checksum sanity), **OpenFoodFacts v2 lookup** (`https://world.openfoodfacts.org/api/v2/product/{code}.json?fields=product_name,brands,quantity,nutriments,image_small_url`, ~8 s timeout, `status:0` = not found), and mapping OFF per-100 g `nutriments` → the app's per-100 g shape (`caloriesPer100g`, `proteinPer100g`, `carbsPer100g`, `fatPer100g`) so the existing `scaleFoodNutrition(food, grams)` applies unchanged.

**New module `src/utils/productCache.js`:** IndexedDB store `calorieiq_products` keyed by barcode — every scanned/found product is cached (cap ~400 entries, FIFO), so repeat scans log instantly and work fully offline (same philosophy as the tile cache). Cached products also merge into the local DB food search.

**UI — new "Scan barcode" mode in `AddFoodFlow.jsx`** (third choice next to Local Database / AI):
1. `isSupported()` guard; tap → `scan()`
2. Found → instant cache check, else OFF lookup (loading state)
3. Product card (name, brand, per-100 g macros) → grams + meal type (reuse `FoodLogDrawer`'s grams pattern) → `logMeal({ name, meal_name, calories, protein_g, carbs_g, fat_g, type, items })` — exactly the existing payload shape; product cached
4. **OFF miss → "Not in database" screen** with:
   - **"📷 Read nutrition panel"** — new `@capacitor/camera` dependency; snap/pick a photo of the Nutrition Facts table; Gemini 1.5 Flash vision parses per-100 g macros into JSON (reuses the existing Gemini API-key plumbing in `utils/gemini.js`, new `parseNutritionPanel()` helper) → same product-card flow; result also cached so it logs offline forever after
   - "Enter manually" as last resort (small name + per-100 g macros + grams form)
5. Graceful errors: no camera, permission denied, no API key (photo fallback hidden without key)

**Android build:** assembleDebug must compile with the new plugin + model; on-device camera/barcode testing only (emulator cameras can't scan real barcodes).
